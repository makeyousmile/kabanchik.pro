# Repository Guidelines

## Обзор и цели
Проект: «Онлайн сервис заказа услуг». Цель — веб‑приложение с клиентским интерфейсом на чистом HTML + Pure.css и бэкендом на Go. Документ описывает план реализации, структуру и минимальные правила.

## План реализации (этапы)
1) **Инициализация**: доменные сущности, MongoDB, базовая структура.
2) **API‑контракты**: REST‑эндпоинты, форматы JSON, коды ошибок.
3) **Бэкенд**: сервер на `net/http`, слои handler/service/repo, конфиг, логирование.
4) **Хранилище**: модели, CRUD‑репозитории, индексы.
5) **Фронтэнд**: ключевые страницы и формы на HTML + Pure.css.
6) **Интеграция и тесты**: связка UI/API, валидация, базовые тесты.

## REST API (черновой список)
Базовый префикс: `/api/v1`. Формат ответов — JSON. Ошибки: `{"error":"..."}`.
- `POST /auth/register` — регистрация пользователя/исполнителя.
- `POST /auth/login` — вход, выдача токена.
- `POST /auth/logout` — выход (инвалидация сессии/токена).
- `GET /me` — профиль текущего пользователя.
- `PATCH /me` — обновление профиля.
- `GET /services` — список услуг (фильтры: категория, город, цена).
- `GET /services/{id}` — карточка услуги.
- `POST /services` — создать услугу (исполнитель).
- `PATCH /services/{id}` — обновить услугу.
- `DELETE /services/{id}` — удалить услугу.
- `GET /orders` — список заказов (фильтры: статус, период).
- `GET /orders/{id}` — детали заказа.
- `POST /orders` — создать заказ.
- `PATCH /orders/{id}` — изменить статус (например: new/accepted/done/canceled).
- `POST /orders/{id}/message` — комментарий/сообщение по заказу.

## Структура проекта
Рекомендуемая структура:
- `cmd/server` — входная точка Go‑приложения.
- `internal/handlers` — HTTP‑обработчики (net/http).
- `internal/service` — бизнес‑логика.
- `internal/repo` — доступ к данным.
- `internal/model` — доменные модели.
- `internal/db` — инициализация MongoDB, индексы, конфигурация.
- `web/` — HTML и стили (Pure.css), ассеты.

## Команды разработки (пример)
- `docker compose up --build` — запуск приложения и MongoDB.
- `docker compose down -v` — остановка и очистка томов.
- `go test ./...` — запуск тестов.
- `go fmt ./...` — форматирование кода.

## Стиль и соглашения
- Go: `gofmt`, `camelCase` для функций/переменных, `PascalCase` для структур.
- HTML/CSS: классы `kebab-case`, без инлайновых стилей.

## Тестирование
- Unit‑тесты сервисов/репозиториев, табличные тесты.
- Имена файлов: `*_test.go`.

## Коммиты и PR
- Формат: `feat: ...`, `fix: ...`, `docs: ...`.
- PR: краткое описание и результаты локальных тестов.
